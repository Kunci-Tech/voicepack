THE "exemplars" ARRAY IS LOAD-BEARING. Read this twice.
A channel only uses the exemplars whose paths appear in this array. Nothing
scans the directory. So every exemplar file you emit under "exemplars/<channel>/"
MUST also appear here, written identically — same spelling, same folder, same
.md extension. If you emit a file but forget to list it, the file is written and
then silently ignored: the channel loses its examples and nobody sees an error.
If you list a path but do not emit the file, the import fails outright. If you
have no real posts for a channel, leave the array empty and do not create that
channel file at all.

RULES — each rule must be true, specific and checkable:

{
  "id": "vp-instagram-001",    // vp-<channel>-NNN, numbered from 001
  "text": "Open with a concrete number or a named person, never a claim.",
  "strength": "hard",          // hard = never violate, soft = preference
  "why": "Numbers stop thumbs. Claims get scrolled past.",
  "example": "5,223 loaves since April.",
  "detect": { ... },           // optional, see below
  "source": { "type": "user-teach", "date": "2026-09-20" },
  "confidence": 0.9            // 0.0-1.0. Use 0.5 for anything you inferred.
}

Use "hard" only for things we would never break. Everything else is "soft".
Aim for 3-6 rules per channel. Ten vague rules are worth less than three sharp ones.

"detect" is OPTIONAL and lets the linter check the rule mechanically. Include it
only when the rule is genuinely mechanical. Supported types, with their fields:

  { "type": "regex",             "pattern": "^\s*(we'?re|our)\b", "flags": "im", "message": "" }
  { "type": "maxChars",          "value": 2200, "message": "" }
  { "type": "minChars",          "value": 80,   "message": "" }
  { "type": "maxEmoji",          "value": 2,    "message": "" }
  { "type": "maxHashtags",       "value": 6,    "message": "" }
  { "type": "minHashtags",       "value": 3,    "message": "" }
  { "type": "maxExclamations",   "value": 1,    "message": "" }
  { "type": "maxSentenceWords",  "value": 20,   "message": "" }
  { "type": "maxParagraphLines", "value": 2,    "message": "" }
  { "type": "forbiddenWords",    "words": ["handcrafted"], "message": "" }

Note the last one: it takes "words", NOT "value". Every other type uses "value",
so this is the one place to be careful. Set "message" to something useful — it
is what I will read when the rule fires. Leave it empty only if you have nothing
better to say than the rule text itself.

Do not invent other detect types — anything else is ignored, and a rule that
looks machine-checked but is not is worse than a rule with no detect at all.
